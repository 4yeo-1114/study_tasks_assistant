# W3 FastAPI 与 HTTP 最小 API 设计

## 目标

在保留现有命令行程序的前提下，为学习任务助手增加最小 FastAPI 接口。首个单元只实现查询和新增任务，用一次真实请求串起 HTTP、请求校验、Python 业务逻辑、SQLite 和 JSON 响应。

本单元完成后，学习者应能解释请求数据流，独立运行 API 与测试，根据状态码定位一个典型故障，并独立增加一个小型查询变式。

## 范围

首版接口：

- `GET /tasks`：按 ID 升序返回全部任务，空数据库返回空数组和 `200 OK`。
- `POST /tasks`：接收标题、优先级和可选截止日期，新增后返回完整任务和 `201 Created`。

首版不实现认证、异步数据库驱动、ORM、分页、更新、删除和 PostgreSQL。这些内容在后续单元加入。

## 结构

采用最小三层结构；Pydantic 模型单独放置，避免 HTTP 文件混入数据结构声明：

- `api.py`：创建 FastAPI 应用、声明路由、接收和返回 HTTP 数据。
- `schemas.py`：使用 Pydantic 声明请求与响应的数据结构。
- `service.py`：组织新增和查询用例，把 HTTP 层与数据库细节隔开。
- `repository.py`：连接 SQLite，建表并执行参数化查询。

已有 `main.py` 和 CLI 行为保持可运行。本单元不进行无关重构。API 直接使用与现有表兼容的字段：`id`、`title`、`status`、`priority`、`due_date`。

## Pydantic 的职责

首版继承 `BaseModel` 的数据模型由 AI 编写，学习者负责阅读并解释，例如 `TaskCreate`。模型声明哪些字段可以出现、字段的 Python 类型、默认值及简单约束；后续变式需要修改请求结构时，再由学习者改模型。

FastAPI 收到 JSON 后调用 Pydantic 完成解析和校验。请求缺少必填字段、类型错误或不符合约束时，框架返回 `422 Unprocessable Entity`，无需在路由中手写 JSON 解析与错误响应。

数据库规则仍由应用负责。例如唯一性、权限、事务和不存在的记录不能全部交给 Pydantic。

## 请求数据流

新增请求的数据流：

1. 客户端发送 `POST /tasks` 和 JSON 请求体。
2. FastAPI 根据方法和路径选择路由。
3. Pydantic 把 JSON 校验并转换为 `TaskCreate`。
4. 路由把已校验的数据交给业务服务函数。
5. 业务服务调用数据访问函数，后者执行参数化 `INSERT`、提交事务并读取新增行。
6. FastAPI 根据响应模型序列化任务，返回 `201` 和 JSON。

查询请求的数据流：客户端发送 `GET /tasks`，路由调用数据访问函数执行 `SELECT`，查询结果经响应模型序列化后以 `200` 返回。

## 数据库与配置

应用默认使用 `study_task_assistant/tasks.db`。数据库路径通过应用工厂参数或依赖函数注入，使测试可以使用临时 SQLite 文件，不接触真实学习数据。

每次数据库操作使用短连接，并确保连接关闭。SQL 使用 `?` 占位符，禁止拼接请求数据。

## 错误与状态码

- 正常查询：`200 OK`。
- 正常新增：`201 Created`。
- 请求字段不合法：`422 Unprocessable Entity`。
- 路径不存在：FastAPI 默认返回 `404 Not Found`。
- 未处理的应用或数据库异常：`500 Internal Server Error`；学习时只在测试环境制造并观察，不把故障逻辑保留在正式实现中。

## 测试设计

使用 pytest 和 FastAPI `TestClient`，测试临时 SQLite 数据库：

- 空数据库执行 `GET /tasks` 返回 `200` 和 `[]`。
- 合法 `POST /tasks` 返回 `201`、完整字段和递增 ID；随后查询可以读到该任务。
- 空标题、非法优先级或非法日期返回 `422`，数据库中不产生任务。
- 未定义路径返回 `404`。

实现遵循测试驱动：先写一个会因 API 尚不存在而失败的行为测试，确认失败原因，再写最小代码通过；其余行为逐个重复。

## 学习者与 AI 分工

AI 负责项目骨架、Pydantic 模型、数据库访问样板、两个路由和基础测试。学习者负责：

1. 用自己的话解释一次完整请求数据流。
2. 运行服务、测试和至少一组 HTTP 请求。
3. 根据路径、状态码、响应体和日志定位一次 `404`、`422` 或测试环境 `500`。
4. 独立增加一个小变式：为 `GET /tasks` 增加可选 `status` 查询参数，并补一个测试。

功能运行通过只证明实现可用。完成解释和操作可达到 L2，完成证据驱动排错可达到 L3，独立完成并验证筛选变式可形成 HTTP/FastAPI 的 L4 证据。

## 验收

- CLI 原有测试继续通过。
- 新 API 测试全部通过，测试不修改真实 `tasks.db`。
- 服务可通过 Uvicorn 启动，并能使用 `/docs` 或 HTTP 客户端访问。
- 学习者能够说明客户端、路由、Pydantic、数据库和响应各自的职责。
- 学习记录如实区分 AI 实现和学习者完成的解释、排错与变式。
