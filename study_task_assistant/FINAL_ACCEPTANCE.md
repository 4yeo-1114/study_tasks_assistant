# 最终验收场景

这些场景用于 W11 的演示和面试复盘。每条场景都要记录输入、HTTP 状态、关键日志、数据库变化和最终结果。

## 1. 查询当前用户的任务

1. 在 `/app/` 注册并登录用户 A。
2. 通过任务接口或页面创建一条任务。
3. 在 Agent 工作台提问“查询我的待办任务”。

预期：Agent 通过只读任务工具查询，返回用户 A 的任务；日志中能用 `X-Request-ID` 找到对应 Agent run 和 tool call。

## 2. 查询当前用户的资料

1. 上传一份资料，例如包含唯一短语“青石 4729”。
2. 等状态为 `ready`。
3. 在 Agent 工作台询问“资料里提到的短语是什么”。

预期：Agent 调用 `search_knowledge`，回答引用 `[来源: source#chunk_id]`；候选资料只来自当前用户。

## 3. 没有资料时拒答

1. 使用没有上传资料的用户，或询问资料中不存在的问题。

预期：检索返回空结果，Agent 明确说明无法从资料库确认，不根据自身知识编造答案。

## 4. 未知工具被拒绝

通过测试 transport 或模型模拟返回不在白名单中的工具名。

预期：Agent 在工具校验阶段失败，API 返回 422；未知工具不会执行数据库操作。

## 5. 创建任务需要确认

1. 在 Agent 工作台请求“创建一条任务”。
2. 检查返回的 pending proposal。
3. 不点击确认，刷新任务列表。

预期：提案已经保存，但 `tasks` 表没有新增记录。点击“确认创建”后，才在同一事务中创建任务。

## 6. 重复确认和重试不重复写入

1. 对同一个 `proposal_id` 连续发送两次确认。
2. 或重复提交相同的模型创建请求。

预期：确认后的重复操作不会创建第二条任务；已确认提案返回冲突或已有任务结果，幂等键阻止重复提案。

## 故障定位顺序

```text
页面/客户端
→ HTTP 状态和 X-Request-ID
→ api 容器日志
→ Agent trace
→ 工具执行日志
→ PostgreSQL 状态、迁移和数据
```

常见状态码：401 表示认证失败，422 表示请求或工具参数不合法，409 表示幂等/状态冲突，429 表示 Agent 预算或步数耗尽，502 表示 DeepSeek 上游失败，503 表示本地运行时或配置不可用。
