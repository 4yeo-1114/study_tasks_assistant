# 学习与健身 Agent 助手升级及共同学习方案

- 确认日期：2026-10-13，Asia/Shanghai。
- 项目：D:/dev-learning/study_task_assistant。
- 目标岗位：Agent 应用开发／Python 后端实习。
- 参考投入：4～6 周，每周 15～20 小时；按理解与验收推进，不按日历自动完成。

## 教学约定

每单元：完整讲解 → 3～5 道理解题及集中批改、完整标准答案 → AI 实现与自动化测试 → 用户自主阅读和随问随答 → 1～2 个非测试变式 → 检查纠错、总结和记录。

AI 负责样板、测试、评测运行器；用户负责需求判断、关键修改、真实运行、故障定位和技术解释。AI 实现和运行不计作用户独立能力。不得先批量实现整个项目再要求用户补学。

## 产品与技术决定

- 保留 FastAPI、SQLAlchemy、Alembic、PostgreSQL/pgvector、FastEmbed、DeepSeek、Compose。LangGraph 用于持久状态和暂停恢复，不预设性能收益；沿用前端并模块化。
- 健身记录训练日期、动作、重量、次数、体重；CSV 先预览校验再提交，重复导入幂等。训练量为 Σ重量×次数，纪录限定同动作比较，体重展示周均趋势，不宣称肌肉／体脂变化。
- 用户档案明确保存目标、频次、偏好、限制和每日分钟预算，支持查看、修改、删除；模型提议的更新需确认，不自动永久记忆任意对话。
- 周计划按日期和每日分钟预算安排；服务端检查预算、频次及档案约束。不做精确日历排程。调整来自实际完成和训练记录；信息不足明确说明。
- 模型只能提议计划改动；确认前不修改正式任务。确认整批事务写入，跨请求幂等键与计划版本检查防重复、防旧提案覆盖。
- 增加训练、体重、导入、档案、周计划及版本接口；聊天增加可选会话 ID，返回运行 ID、结构化引用与计划提案。所有对象按可信用户身份隔离。
- 中文分词后的 PostgreSQL 全文索引替代全量正文读取后评分，保留 pgvector＋RRF；全文排名不称为 BM25。
- 批量向量化在写入事务外完成，短事务写入，新版本完成后激活；文本 PDF 保留页码，扫描件明确不支持。
- 生产链路验证引用来自有效证据；修复先空后命中仍拒答；开发集校准证据不足判断。引用身份合法与语义支持分开评价。

## 评测合同

- 质量集 120 条：开发 40，冻结验收 80；标注相关 chunk 和无答案场景。对比关键词、向量、RRF，报告 Recall@5、MRR@5、无答案正确率；来源命中率不称为 Recall。
- 使用独立实验库，1,000／10,000 chunk；固定硬件、模型、语料、查询，预热后 100 查询、5 轮。记录检索 P50/P95、入库 chunks/s、事务耗时，合成扩容数据明确标记。
- 精确向量检索对照 HNSW；报告邻居召回、延迟与 EXPLAIN，检查用户过滤后的数量和正确性。
- 至少 60 个确定性 Agent 场景，覆盖会话、档案、计划约束、授权、重试、确认、冲突、预算。在线模型单独运行、统计 Token、实际费用和失败样本。
- 保留回归并补 PostgreSQL 并发及浏览器端到端测试；覆盖跨用户、重复导入、旧版本保留、重启恢复和确认回滚。
- 保存提交 ID、工作区状态、数据哈希、配置、原始 JSON/CSV、命令及报告。未提交代码不能仅用 HEAD 标识；需要工作区快照或内容哈希。
- 先测基线再优化；不承诺提升百分比。区分百分比和百分点，不把单次日志、离线替身或合成数据结果改写为生产指标。

## 范围与求职输出

首版本地低成本；不接设备、不做 OCR、多 Agent、医疗建议或精确日历。最终 4～5 条简历亮点包含问题、选择、实测结果、范围；同步准备失败案例和贡献说明。
